- HSTS is a Cloudflare zone setting (SSL/TLS → Edge Certificates), not nginx. Set to 12 months on 2026-11-05. Never add it in nginx too, or responses get two headers. The Agents vault Cloudflare token (item "Cloudflare Read Only", despite the title) can purge the cache since 2026-11-06: `op run` with `op://Agents/Cloudflare Read Only/credential`, zone `ccfcdf549dadb6a694c28af678eef0ad`, `POST /zones/<zone>/purge_cache`. Purge after any release that changes HTML, since APO serves the old pages. Zone settings are still Ivan's to change.
- nosniff, X-Frame-Options, Referrer-Policy and COOP live in `docker/nginx/default.conf`, repeated in the two static `location` blocks. COOP is `same-origin-allow-popups`, not `same-origin`, because Site Kit's wp-admin screens use `window.open` (v0.28.1).
- CSP: design in `docs/specs/2026-11-05-strict-csp-design.md` (nonce at print time, Report-Only first, no report collector). Report-Only shipped in v0.29.0 (PR #73, 2026-11-05) as `IK2\Plugin\Csp` (`wp-content/plugins/ik2/inc/csp/`); `const ENFORCE` in `namespace.php` switches Report-Only to enforce. `pnpm test:csp` crawls the flows (`CSP_COOKIE` adds a logged-in pass). On prod (checked 2026-11-05), Cloudflare copies the header's nonce onto the Web Analytics beacon, which is undocumented but works. Email obfuscation is different: its `email-decode.min.js` gets no nonce, and no header allowlist can admit it under `'strict-dynamic'`. Ivan wants the setting kept on and no Worker, so `IK2\Plugin\Email` encodes every address in `the_content` with `antispambot()` (v0.29.1) and wraps `mailto:` links in Cloudflare's `<!--email_off-->` comments (v0.29.2), because Cloudflare decodes entities in `href` and still rewrote them. Fresh prod renders on 2026-11-05 showed no rewrite and no decode script. Cloudflare strips the email_off comments from the output. Local and prod post IDs differ, so the crawl uses slugs. There's no prod shell, so the prod crawl's logged-in pass needs Ivan's cookie in `CSP_COOKIE`.
- Prod crawl after v0.29.2 (2026-11-05) found a second router violation, `script-src` `eval` from `interactivity-router/index.min.js:3`, on `/articles/` filter navigation. It's es-module-lexer's `(0,eval)(s)` unquoting import specifiers while the router rewrites modules into blob URLs. `'wasm-unsafe-eval'` doesn't cover it, and the local crawl doesn't hit it. Under enforcement it fails inside a try/catch. Find out what breaks before flipping `ENFORCE`.
- Core's Interactivity router bundles a WebAssembly module lexer (`WebAssembly.compile`), so `/articles/` filter navigation raises a `script-src` `wasm-eval` violation. Under enforcement, filter clicks still navigate client-side. Ivan approved `'wasm-unsafe-eval'` and it is now in Q4 and the policy. Chrome reports `PrerenderingDisabledByDevTools` for any tab a DevTools client drives, so prerender checks are manual.
- Core already sends `Content-Security-Policy: frame-ancestors 'self'` on `wp-login.php`, on prod too. That isn't ours, and it isn't the strict CSP.
- On 2026-11-05 a random query string (`/?r=<n>`) went MISS then HIT with its own nonce, but Cloudflare's APO docs say query strings bypass the cache by default. Something in the zone overrides that, cause not found. Zaraz doesn't modify a Report-Only header (Cloudflare blog, 2022), so Report-Only testing can't show whether Zaraz is on. Check it in the dashboard before enforcing.
- APO caches HTML with its headers, so header changes show only on a `cf-cache-status: MISS` until Ivan purges.
- Edit `default.conf` with Edit, not `sed -i`: macOS `sed -i` swaps the inode, the single-file bind mount loses it, and `nginx -t` fails until `docker compose restart nginx`.
